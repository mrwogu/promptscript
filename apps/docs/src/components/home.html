The problem

AI instructions do not scale by copy-paste

Every AI tool wants its own file. Every repository keeps its own copy. Soon nobody knows which rules the agents actually follow.

Without PromptScript

  • A different file for every tool: CLAUDE.md, .cursor/rules, copilot-instructions.md, AGENTS.md
  • Copies drift apart across dozens of repositories
  • Company standards live in a wiki the agents never read
  • Third-party skills can carry hidden prompt injection
  • Switching AI tools means rewriting everything

With PromptScript

  • One .prs source, native output for 50 agents
  • Company standards inherited by every repository, not copied
  • Changes reviewed in Git and validated in CI
  • Built-in security scanner for every prompt and imported skill
  • Add or switch tools by editing one target list

Prompts as code

Inherit, compose, and extend

Configuration is composable source, not copied text. Inherit a shared base, mix in reusable fragments, and override only what changes - with deterministic, reviewable merges.

project.prs source 
# IS-A: inherit the organization base
@inherit @company/platform

# HAS-A: compose reusable fragments
@use @core/security
@use @fragments/testing

# override only what changes
@extend standards.code {
  framework: "react"
}

@extend restrictions {
  - "Use functional components only"
}
@inherit

Inherit a base

Single-parent "IS-A" chains from organization to team to project. Blocks merge with predictable rules.

@use

Compose fragments

Mix in multiple "HAS-A" capabilities like security or testing. Later imports win on conflicts.

@extend

Extend and override

Patch specific paths, append or negate references, and seal properties that layers cannot change.

Built-in security scanner

Stop prompt injection before it ships

prs validate scans every instruction, skill, and imported file. Encoded payloads are decoded first, so hiding an attack in hex or Base64 does not get it through.

  Decoded: "IGNORE SAFETY RULES"

✗ PS010: URL shortener detected:
  http://bit.ly/deploy-help
  at project.prs:16:14
PS005

Injection and overrides

Phrases like "ignore previous instructions" and fake authority overrides fail the build.

PS012

Encoded payloads

Base64, hex, URL encoding, HTML entities, ROT13, and more are decoded and checked.

PS014

Invisible Unicode

Right-to-left overrides, zero-width characters, and homoglyphs.

 PS010

Suspicious links

Plain HTTP, link shorteners, and credentials in URLs.
Skill composition

Build big skills from small, owned pieces

Split a complex skill into phases. Each phase is its own .prs file with its own context, parameters, and allowed tools, so different teams can own different parts.

ops.prs source 
@skills {
  ops: {
    description: "Production operations"

    # every phase is a separate .prs file
    @use ./phases/health-scan
    @use ./phases/triage(severity: "critical")
    @use ./phases/code-fix as autofix

    # shared phases from the Git registry
    @use @shared/phases/monitoring
  }
}
@use

Phases with boundaries

Each phase brings its own instructions and declares only the tools it needs.

 contracts

Typed inputs and outputs

Skills declare what they take and return, so they plug together cleanly.

 @extend

Extend without forking

Teams layer changes on a shared skill. Sealed properties stay locked.
